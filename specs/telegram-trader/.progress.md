## Original Goal

# Telegram Trader

Use the golang telegram API and gswap/galachain typescript API (an example working bot using galachain gswap is here: https://github.com/cchuter/gswap-bot).

Trade assets on ston.fi and gswap.

In telegram, a user will be presented with these instructions after starting the bot:

```
🚀 Welcome to GalaSwap & STON.fi Trading Bot!

Trade tokens on GalaChain and TON blockchain with ease.

Available Commands:
/wallet - Connect your TonKeeper wallet
/balance - View your balances
/swap - Execute a token swap
/price - Check token prices
/alert - Set price alerts
/portfolio - View your portfolio
/orders - Manage automated orders
/help - Show all commands

Get started by connecting your wallet with /wallet
```

The user will be able to connect their TON wallet via Tonkeeper (app on iphone)

The user will be able to connect their GALA wallet via the gala wallet app (on iphone)

prices return valid token values retreived from either chain, TON or GALA (if the user doesn't specify it returns form both chains)

the TON token is GTON on galachain

the main pair we are interested in is:
on ston.fi: https://app.ston.fi/swap?chartVisible=false&ft=TON&tt=EQBadmOayy7_bD18skopfOZw2kmTgDdBhXPVsuTQq1lalaBV
on gswap: https://swap.gala.com/explore-balance/2954bd1e38c2dff11a2ee8798e2f59b99c206e64bef7bdf5c4ac9a91315e0d34

Give the ability to do spread arbs: Add add a "arb" command that looks at those proces and if they're .1% different does a trade of 50% of either asset (always eaving at least 10 gala or 1 TON). The goal is to buy when one token is less expensive on one chain and sell if its higher on the other - between the TON/GALA pair.

## Learnings

- JSON logging enables easy parsing/filtering in production monitoring tools
- LOG_FORMAT env var allows switching between JSON (prod) and text (dev) formats
- TypeScript Logger class matches Go logger structure for consistency across services
- All production code should use structured logging, not console.log or fmt.Println
- Public bot requires robust authentication, rate limiting, and abuse prevention
- PostgreSQL uses $1, $2, ... for parameterized queries (vs ? for SQLite)
- PostgreSQL native BOOLEAN type vs SQLite INTEGER for is_active field
- Connection pooling critical for PostgreSQL (25 max connections vs SQLite single writer)
- schema_migrations table pattern enables idempotent migrations across environments
- Correlation IDs enable end-to-end request tracing across microservices architecture
- gRPC metadata key "x-correlation-id" used for passing correlation IDs between services
- UUID v4 provides sufficient uniqueness for correlation ID generation
- Including correlation ID in error messages helps users report issues with traceable context
- Speed of delivery priority suggests MVP approach with phased rollout
- Arbitrage execution requires sub-second timing and careful risk management
- Recommended 0.3% spread threshold (vs 0.1%) for reliability
- Greenfield microservices architecture with gRPC inter-service communication
- Complete file structure defined: 60+ files across Go and TypeScript services
- Production-ready deployment strategy with Kubernetes and monitoring
- POC-first workflow: 28 tasks to get it working, then refactor, test, and polish
- Standard testing approach: unit + integration tests (70% coverage target)
- Local development focus: docker-compose priority, defer Kubernetes
- go-telegram/bot library provides clean API with handler registration pattern - handlers accept context, bot instance, and update as parameters
